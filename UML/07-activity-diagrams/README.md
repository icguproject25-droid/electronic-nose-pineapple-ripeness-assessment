# 第七章 活動圖（Activity Diagrams）

本資料夾整理「水果（鳳梨）電子鼻非破壞性熟度檢測系統」第七章所需之活動圖。  
活動圖主要用來描述各使用案例的執行流程、參與者責任分工、正常路徑與例外路徑，使系統功能不只停留在使用案例名稱，而能進一步呈現實際的操作步驟與系統處理邏輯。

本章活動圖依據第六章使用案例描述與情節設計，並對照設計規格書中消費端 App、農民端 App、Raspberry Pi、Arduino Mega、感測器陣列、ExtraTrees 模型、Flask 測試介面與照片辨識 API 等實際系統模組進行繪製。

---

## 1. 本章目的

活動圖可視為傳統流程圖的延伸，能夠用來塑模系統層級的處理邏輯或執行程序。  
在本專題中，活動圖的主要目的如下：

1. **塑模系統層級的處理流程**  
   將消費者掃描、農民批次管理、空氣基線校正、模型推論與照片品種辨識等流程，以圖形方式表示。

2. **補足使用案例描述的細節**  
   使用案例圖只能表示系統提供哪些功能，而活動圖可以進一步表示功能如何一步一步執行。

3. **檢驗使用案例描述是否合理**  
   透過活動圖可以確認每個主要路徑是否能順利到達成功條件。

4. **找出例外路徑與錯誤處理**  
   例如感測器連線失敗、資料不足、JSON 格式錯誤、批次資料讀取失敗、照片未偵測到鳳梨等情況。

5. **區分不同參與者的責任**  
   使用 swimlane（水道）區分使用者、App、Raspberry Pi 3、Arduino Mega、批次資料庫、模型與 API 等角色。

## 2. 繪製原則

本資料夾中的活動圖採用以下原則設計：

| 原則 | 說明 |
|---|---|
| 使用水道 Swimlane | 依參與角色區分責任，例如消費者、農民、App、Raspberry Pi 3、Arduino Mega、批次資料庫等 |
| 使用起始節點與終止節點 | 每張圖皆以起始節點開始，並以活動終止節點或流程終止節點結束 |
| 使用動作節點 | 以圓角矩形表示使用者操作或系統處理動作 |
| 使用決策節點 | 以菱形表示條件判斷，例如是否成功、是否有資料、是否符合格式 |
| 使用 Guard 條件 | 在分支線上標示條件，例如「成功 / 失敗」、「有 / 沒有」、「是 / 否」 |
| 納入主要路徑 | 每張圖皆包含第六章使用案例描述中的正常情節 |
| 納入例外路徑 | 每張圖皆補入錯誤、失敗、取消、資料不足等情境 |
| 避免線條壓字 | 圖片版活動圖已調整線距與節點位置，避免控制流程線覆蓋文字 |

### 4.1 UC-01 消費者開始掃描鳳梨活動圖

此圖描述一般消費者透過 App 啟動單顆鳳梨成熟度掃描的流程。  
流程包含使用者開啟 App、點擊開始掃描、放入鳳梨、系統檢查 Air Baseline、Raspberry Pi 檢查 Serial 連線、Arduino 讀取 VOC 與環境感測資料、Raspberry Pi 收集 30 秒資料、計算 11 項部署特徵、載入 ExtraTrees 模型推論，最後由 App 顯示成熟度、信心值與食用建議。

此圖也補入例外路徑，例如尚未校正、感測器連線異常、30 秒資料不足等情況。

### 4.2 UC-02 消費者查看成熟度結果活動圖

此圖描述掃描完成後，消費者查看成熟度結果的流程。  
系統會從模型推論系統取得 JSON 結果，App 解析 Stage、信心值與建議內容，依照成熟度 Stage 顯示不同顏色標籤，並將結果儲存至歷史紀錄。

例外路徑包含後端沒有回傳結果、JSON 格式錯誤、信心值過低、結果儲存失敗等情況。

### 4.7 UC-07 農民執行批次掃描活動圖

此圖描述農民針對已建立批次進行多顆鳳梨連續掃描的流程。

### 4.8 UC-08 農民查看批次結果活動圖

此圖描述農民查看指定批次結果的流程。

### 4.10 UC-10 農民查看批次歷史活動圖

此圖描述農民查看、搜尋與管理歷史批次資料的流程。  
農民進入批次歷史頁面後，系統讀取歷史批次資料並依日期排序。農民可輸入日期或關鍵字篩選批次，選擇其中一個批次後，系統顯示該批次的掃描紀錄與統計結果。農民也可選擇刪除某筆批次紀錄。

例外路徑包含批次歷史讀取失敗、沒有任何歷史批次、查無符合條件的批次、刪除取消等情況。

### 4.11 UC-11 系統執行空氣基線校正活動圖

此圖描述系統執行 Air Baseline 校正的流程。  
開發者、測試人員或系統管理者進入 Flask 測試介面後，確認環境中沒有鳳梨或強烈揮發物，點擊 Air Baseline 校正。系統啟動 calibrate_air_30s.py，Raspberry Pi 嘗試開啟 Serial Port，Arduino 讀取無鳳梨環境下的空氣背景資料，Raspberry Pi 收集 30 秒空氣資料，計算各感測器 mean、std、min、max，最後產生 airbase.json。

例外路徑包含 Serial Port 連線失敗、無法取得感測資料、校正資料波動過大、環境中存在干擾氣味、airbase.json 儲存失敗等情況。

![UC-11 系統執行空氣基線校正活動圖](./7-11%20UC-11系統執行空氣基線校正活動圖.png)

### 4.12 UC-12 系統進行模型推論活動圖

此圖描述系統模型推論的內部流程。  
Raspberry Pi 接收到推論請求後，依序載入 airbase.json、deploystudent.pkl 與 featurecolumns.json，接收 Arduino 傳來的感測資料並累積 30 秒資料窗口。資料足夠後，系統計算 11 項部署特徵，使用 airbase.json 進行歸一化，交由 ExtraTrees 模型輸出 Stage 0～Stage 3 機率分布，再套用 Guard Baseline 與 Override 後處理規則，最後由 App 顯示成熟度結果。

例外路徑包含 airbase.json 不存在或無效、模型檔案不存在、featurecolumns.json 不存在、30 秒資料不足、模型輸出格式錯誤等情況。

![UC-12 系統進行模型推論活動圖](./7-12%20UC-12系統進行模型推論活動圖.png)

## 7. 補充說明

本章活動圖主要呈現系統的動態流程，與第八章類別圖不同。  
活動圖關注的是「流程如何執行」，例如使用者如何操作、系統如何判斷、錯誤如何處理；類別圖則關注「系統有哪些類別與資料結構」，例如 User、ScanRecord、Batch、Report、InferenceEngine 等類別及其關係。

因此，本章活動圖可作為後續系統實作、測試案例設計與使用者操作說明的重要依據。
